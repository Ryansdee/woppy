## Détails

### 0. Build cassé sans les clés serveur
`src/app/api/admin/analytics/route.ts` et `src/app/api/reviews/route.ts` initialisaient Firebase Admin au chargement du module. Sans `FIREBASE_ADMIN_*` (absentes du `.env.local`), Next.js plantait pendant la collecte des pages : `Service account object must contain a string "project_id" property`. Netlify n'était pas touché tant que ses variables sont définies, mais n'importe quel build local ou de preview cassait.
**Correction** : `src/lib/firebaseAdmin.ts` expose `getAdminDb()` et `getAdminAuth()`, qui initialisent l'app au premier appel. Les deux routes les utilisent, ce qui supprime aussi le code d'init dupliqué.

### 1. Dépendances non installées
`recharts` est déclaré dans `package.json` mais n'était pas dans `node_modules`, donc `tsc` échouait sur `src/app/dashboard/recap/page.tsx:39`. Un `npm install` a réglé le problème. Sur Netlify l'installation se fait à chaque build : la production n'était pas touchée.

### 2. `/admin/fix-chats`
`src/app/admin/fix-chats/page.tsx` lance au chargement une boucle `updateDoc` sur toute la collection `chats`, sans vérifier le rôle. La page dit elle-même « Une fois fini, supprime-la ». Seules les règles Firestore empêchent un visiteur quelconque de lancer ces écritures.
**Action proposée** : supprimer la page (le script `scripts/fixChat.js` fait le même travail).

### 3. Règles de sécurité non versionnées
Aucun `firestore.rules` ni `storage.rules` dans le dépôt, et `firebase.json` ne déclare que les functions. La sécurité réelle de l'app dépend donc de règles qu'on ne peut ni relire ni tester ici.
**Action proposée** : exporter les règles depuis la console Firebase et les ajouter au dépôt.

### 4. Cloud Functions en double
`functions/package.json` pointe sur `index.js` (`sendPushFromNotification`). `functions/src/index.ts` (`sendPushNotification`, `sendBulkNotifications`) n'est pas compilé ni déployé par cette configuration.
**Action proposée** : choisir une seule version.

### 5. Lint
Répartition : `no-explicit-any` 122, `no-unescaped-entities` 107, `no-unused-vars` 33, `no-img-element` 12, règles React Hooks 12, `jsx-key` 4, `no-unused-expressions` 2.
Les alertes `jsx-key` et `react-hooks/immutability` relues à la main sont des faux positifs (clés présentes, fonctions appelées après déclaration). Rien de bloquant, mais le bruit cache les vraies erreurs.

### 6. `/api/github-sync`
Chaque appel fait 1 + 30 requêtes à l'API GitHub sans jeton (limite : 60 par heure et par IP). Le cache `revalidate` limite le risque, mais la page `/updates` peut tomber en panne si le cache est vide.

### 7. Stripe
Le paquet `stripe` et `@stripe/stripe-js` sont installés pour rien tant que les paiements ne sont pas développés.

### 8. Design
`layout.tsx` force un fond `#f5e5ff` en style inline, `globals.css` contient le thème sombre du modèle Next.js (inutilisé), et chaque page définit ses propres couleurs et polices (`Sora`, Geist, Arial). C'est la base de la refonte de l'interface.
